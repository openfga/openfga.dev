In this guide you will learn how to grant a [user](/docs/concepts#what-is-a-user) access to a particular [object](/docs/concepts#what-is-an-object).

<Note>
**When to use**

Granting access with a _[relationship tuple](/docs/concepts#what-is-a-relationship-tuple)_ is a core part of OpenFGA. Without any relationship tuples, any _[check](/docs/concepts#what-is-a-check-request)_ will fail. You should use:

- _authorization model_ to represent what **relation**s are possible between the users and objects in your system
- _relationship tuples_ to represent the facts about the relationships between users and objects in your system.
</Note>

## Before you start

In order to understand this guide correctly you must be familiar with some [OpenFGA Concepts](/docs/concepts) and know how to develop the things that we will list below.

Assume that you have the following [authorization model](/docs/concepts#what-is-an-authorization-model).<br />
You have a [type](/docs/concepts#what-is-a-type) called `tweet` that can have a `reader`.

<Accordion title="Prerequisites and starting model">

            this: {},

### Direct access

You need to know how to create an authorization model and create a relationship tuple to grant a user access to an object. [Learn more →](/docs/modeling/direct-access)

<h3 id="-concepts">OpenFGA concepts</h3>

- A [Type](/docs/concepts#what-is-a-type): a class of objects that have similar characteristics
- A [User](/docs/concepts#what-is-a-user): an entity in the system that can be related to an object
- A [Relation](/docs/concepts#what-is-a-relation): is a string defined in the type definition of an authorization model that defines the possibility of a relationship between an object of the same type as the type definition and a user in the system
- An [Object](/docs/concepts#what-is-an-object): represents an entity in the system. Users' relationships to it can be define through relationship tuples and the authorization model
- A [Relationship Tuple](/docs/concepts#what-is-a-relationship-tuple): a grouping consisting of a user, a relation and an object stored in OpenFGA

</Accordion>

## Step by step

### 01. Adding direct relationship

For our application, we will give user Anne the `reader` relationship to a particular `tweet`. To do so we add a tuple as follows:

Anne can read tweet:1

```json
[
  {
    "user": "user:anne",
    "relation": "reader",
    "object": "tweet:1"
  }
]
```

With the above, we have added a [**direct** relationship](/docs/modeling/building-blocks/direct-relationships) between Anne and `tweet:1`. When we call the Check API to see if Anne has a `reader` relationship, OpenFGA will say yes.

<CheckRequestViewer user={'user:anne'} relation={'reader'} object={'tweet:1'} allowed={true} />

### 02. Removing direct relationship

Now let's change this so that Anne no longer has a `reader` relationship to `tweet:1` by deleting the tuple:

<WriteRequestViewer
  deleteRelationshipTuples={[
    {
      user: 'user:anne',
      relation: 'reader',
      object: 'tweet:1',
    },
  ]}
/>

With this, we have removed the [direct relationship](/docs/modeling/building-blocks/direct-relationships) between Anne and `tweet:1`. And because our type definition for `reader` does not include any other relations, a call to the Check API will now return a negative response.

<CheckRequestViewer user={'user:anne'} relation={'reader'} object={'tweet:1'} allowed={false} />
